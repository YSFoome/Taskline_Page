# Taskline · 个人任务台

一个面向个人的离线优先任务 PWA。任务先保存在浏览器 IndexedDB，手动同步时通过 GitHub Contents API 写入你指定的私有仓库。

## 本地开发

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run check
npm run build
```

## GitHub 数据仓库配置

1. 新建一个独立的私有仓库，建议初始化 README，让 `main` 分支先存在。
2. 创建 fine-grained personal access token，只选择这个数据仓库，并授予 `Contents: Read and write`。
3. 打开 Taskline 的“设置”，填写 Owner、Repository、分支、数据文件路径和令牌。
4. 点击“保存连接”和“测试连接”，然后通过“推送本地”初始化 `task-data/snapshot.v1.json`。

同步操作有三种：

- “从远端拉取”：用 GitHub 快照替换本机任务；如果本机有未同步修改，会先要求确认。
- “推送本地”：把本机快照写入 GitHub；会先确认可能覆盖远端当前文件。
- “合并同步”：拉取远端后，以共同基线做三方合并，再把合并结果推回 GitHub；同一字段发生冲突时保留冲突供选择。

## Windows 与手机的日常使用

### 第一次在每台设备上连接

同步配置和 PAT 只保存在当前设备的浏览器 IndexedDB 中，不会随任务快照同步。因此 Windows 电脑、iPhone 等每台设备都需要各自完成一次连接：填写同一个 Owner、Repository、分支和文件路径，并在该设备输入 PAT。可以为每台设备填写不同的设备名称，方便在 GitHub 提交历史中识别来源。

建议先在一台设备完成初始配置并点击“推送本地”，确认私有仓库中已经出现 `task-data/snapshot.v1.json`，再在其他设备配置并点击“从远端拉取”。

### Windows Edge / Chrome

1. 用浏览器打开 Taskline 页面，按上面的步骤完成 GitHub 连接。
2. 安装为应用：
   - Edge：地址栏右侧选择“应用” → “将此站点安装为应用”。
   - Chrome：地址栏右侧选择“安装 Taskline”或菜单“投放、保存和分享” → “安装页面”。
3. 以后从开始菜单、桌面或任务栏打开 Taskline；没有网络时仍可新增、编辑、拖动、完成和归档任务。
4. 工作开始前点击“合并同步”，把其他设备的修改拉到本机并处理冲突。
5. 工作过程中只需正常编辑；修改会立即保存到本机，顶部会显示未同步数量。
6. 工作结束或准备切换设备时点击“合并同步”。只想单向操作时使用“从远端拉取”或“推送本地”。

### iPhone / iPad Safari

1. 在 Safari 打开 Taskline 页面，完成本设备的 GitHub 连接；Safari 不会自动取得电脑上的 PAT。
2. 点击“分享” → “添加到主屏幕” → “添加”，从主屏幕图标启动。首次看不到该选项时，在分享菜单底部向上滚动查找。
3. 日常使用方式与 Windows 相同：离线时照常记录，联网后手动点击“合并同步”。
4. 手机上看板支持横向滑动；不能或不方便拖动时，打开任务详情使用“移动到……”菜单。日历任务可用日期选择器移动。
5. 在手机上执行“从远端拉取”前，如果提示本机有未同步修改，请先确认这些修改已经推送，或改用“合并同步”避免覆盖。

Android Chrome 可用浏览器菜单中的“安装应用”或“添加到主屏幕”，之后按同样的离线记录、联网后手动同步流程使用。

### 多设备切换约定

- 切换到另一台设备前，先在当前设备点击“合并同步”，等待顶部显示新的同步时间。
- 新设备或长时间未使用的设备，先点“合并同步”；如果只需要完全采用云端内容，可点“从远端拉取”。
- “推送本地”会覆盖 GitHub 数据文件的当前内容，适合确认本机就是最终版本时使用；应用会先弹出确认，并用 SHA 检查已知的远端变化。
- 同一字段在两台设备上都修改时，合并同步会显示本地值和 GitHub 值，选择后再提交；不要在未处理冲突时反复覆盖推送。
- 顶部只显示最后一次手动同步时间，不做后台或实时同步；关闭页面、断网或重启设备不会丢失已保存的本地任务。

### 页面与高频工作流

- **看板**仍是启动首页。标题右侧的“看板 / 列表”分段控件共用搜索、状态、优先级和标签筛选；列表模式还可以按今天、未来 7 天、本月或自定义日期范围筛选。
- **今日**按“逾期、今天、今日已完成”分组。今日快速新增会自动带上今天的截止日期；已完成任务默认折叠，避免把注意力从待办事项上移开。
- 任务卡片左侧的圆形按钮是一键完成，卡片上的更多按钮会打开即时保存的任务详情。详情中可编辑状态、日期、备注、标签、检查清单、周期和自定义字段。
- 看板、今日和列表都支持“选择”模式：完成圆钮会替换为复选框，底部工具栏可批量归档、改状态、添加或移除标签；批量归档不会删除任务，也不会产生 tombstone。
- **月历**用于按日期浏览和桌面拖动改期；手机先点日期，再在任务详情的日期选择器中改期。**归档**保留历史记录，可从任务详情或列表恢复。
- 外观设置支持跟随系统、浅色、深色和本机主题色。主题色只影响导航、按钮、选择和焦点状态，不会覆盖状态列、优先级或危险提示的语义色。

界面会根据宽度自动切换：桌面使用侧栏和右侧任务支持面板，中等宽度使用带遮罩的抽屉，手机使用五项底部导航和单列看板。所有编辑即时写入 IndexedDB；页面顶部的数字表示相对上次成功同步快照发生变化的任务或结构项数量。

令牌只保存在当前设备的 IndexedDB 中，不会写入任务快照、导出文件或 Git 提交信息。建议为令牌设置合理的过期时间，并在 GitHub 中定期检查和撤销不再使用的令牌。

## GitHub Pages

仓库内的 `.github/workflows/deploy.yml` 会在 `main` 分支变更后构建并发布 `dist`。在 GitHub 仓库设置中启用 Pages，并把发布来源设为 GitHub Actions。代码仓库可以公开；任务数据始终使用另一个私有仓库。

## 数据格式

同步文件是带 `schemaVersion` 的 JSON 快照，包含看板列、自定义字段、任务、检查清单、周期规则和删除标记。日期使用 `YYYY-MM-DD`，时间使用 UTC ISO 字符串。导出文件只包含任务数据，不包含令牌。
